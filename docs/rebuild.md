# Rebuild notes

## What the source did well

The supplied app compared steered output with an unsteered baseline and exposed activations, token effects, and circuit context. Its research log carefully separated observation from interpretation. Those ideas inform the new workflow.

## What made it hard to adapt

The source's `runtime.py` directly imports `Qwen3_5ForConditionalGeneration`, navigates `model.language_model.layers`, expects `mlp.down_proj`, and has model-specific attention hooks. Its `server.py` fetches Qwen architecture metadata at import time and shares Qwen-specific caches. Swapping an environment variable therefore does not adapt the whole application. A large server also combines inference, data ranking, cached connections, agent processes, file access, and UI state.

The screenshot's floating overlapping panels, abbreviated toggles, and multiple parallel workflows demand familiarity before a first experiment is possible. The user explicitly requested keeping the 3D layer view; the rebuild retains it as the main atlas with orbit, zoom, and neuron picking.

## New boundaries

1. `Provider` defines capabilities and operations. An API connection never gets synthetic local-model capabilities.
2. Local models discover their decoder stack and dense MLP projection widths after explicit selection. No model metadata or weights are downloaded when starting the server or opening demo mode.
3. Hooks exist only inside a context manager and are removed even when a forward pass fails. Model operations are serialized. Different profiles do not share neuron observations.
4. The browser renders a 3D layer stack and one selected neuron, with controls named in full. Layers occupy distinct depths and rotate under a perspective camera. Neuron positions are based on index, and no unmeasured circuit edges are drawn. List view and direct index selection remain available. A visible gain value connects the intervention to its response. Results are stored automatically so saving does not interrupt exploration.
5. Demo provenance is explicit throughout the interface, saved experiments, and exports. Theme labels are illustrative and are never attached to live model neurons.

## Extending the application

- **Another dense architecture:** add and validate its decoder-stack and FFN output-projection paths in `local.py`. Validate that projection inputs represent the neuron activations you intend to scale. Test hooks and generation with a small model first.
- **MoE or custom internals:** implement a dedicated provider; expert indices need their own identity and UI. Do not silently flatten expert neurons into dense indices.
- **Another chat protocol:** subclass `Provider` and keep `inspect` / `steer` disabled unless weights and correct intervention hooks are available.
- **Real annotations or sweep imports:** import with explicit model identity, source provenance, layer/neuron bounds, and dose semantics. The original `.npz` caches and model-specific steering doses are not directly compatible.
- **Long-running inference:** add a job API with cancellation and progress before enabling broader context windows or batch research workloads.

No full sweeps, causal circuit claims, automatic neuron interpretations, or statistical controls are generated by this rebuild. Comparisons are individual exploratory observations.
